## AcePanel 部署失败：malformed MIME header: missing colon "Date"

### 任务目标
排查并修复 AcePanel 面板部署证书时持续失败的问题：
`Put "http://100.118.154.24:52464/u5GJ9L/api/website/9": net/http: HTTP/1.x transport connection broken: malformed MIME header: missing colon: "Date"`。

### 执行细节
- 修改 `internal/deploy/panel.go` 的 `panelHTTPClient()`：给 `http.Transport` 增加 `DisableKeepAlives: true` 与 `DisableCompression: true`。
  - 该 transport 经 `httplog.WrapClient` 包裹，被所有面板/防火墙客户端（btpanel/aapanel/1panel/acepanel/aawaf）共用。

### 关键决策（根因分析）
- 确认 Go 的 `http.Transport` **不会**自动添加 `Expect: 100-continue`（仅客户端显式设置才发送），排除该因素。
- 环境无 `HTTP_PROXY`，排除前向代理拦截 PUT。
- 日志特征：GET（ListSites / DeployCert 内 GET）成功，PUT **每次必失败**且极快（发 payload 后 ~21ms 即报连接损坏）；浏览器用同一入口 `/u5GJ9L` 的相同 PUT 能成功 → 服务端本身能返回合法响应，非确定性服务端 bug。
- 决定性差异：流程中先 GET 建立 keep-alive 长连接，随后 PUT 复用该连接；前方隧道/反代入口（CGNAT 地址 + 随机入口路径，典型 frp 类）在**复用连接上处理 PUT 响应**时写出非法头部行 `Date`（缺冒号），net/http 严格解析器判定连接损坏。
- 修复：关闭长连接 + 关闭自动 gzip 压缩，每次请求新建 TCP 连接，规避入口连接复用 bug。

### 验证
- `go build -tags production ./...` 通过（仅 macOS 版本链接警告，既有且无关）。
- 待用户实机复测 AcePanel 部署；若仍失败，则可能是入口确定性返回非法头，需补充「容忍畸形响应头」的裸 HTTP 回退（当前未实现）。

### 遗留问题 / 下一步
- 需用户在 AcePanel 目标上重新触发部署验证。
- 若 DisableKeepAlives 不奏效，考虑在 `internal/deploy` 为 AcePanel PUT 增加原生裸 HTTP 发送+容忍畸形头的回退路径。

## AcePanel 部署改为「上传证书 → 部署证书」两步流

### 背景
用户给出 AcePanel 官方证书接口：
- 证书列表 `GET /api/cert/cert?page=1&limit=20`
- 上传证书 `POST /api/cert/cert/upload` body `{"cert":"...","key":"..."}`
- 部署证书 `POST /api/cert/cert/{id}/deploy` body `{"id":2,"website_id":9,"enable_https":true}`

要求改掉原先「GET 全量站点 → 改 ssl 字段 → PUT 全量替换」的方式（该方式既易因字段缺失踩坑，又正好触发隧道入口在 PUT 复用连接上的畸形响应头 bug）。

### 执行细节
- 重写 `internal/deploy/acepanel.go` 的 `DeployCert`：
  1. `client.doJSONRequest(ctx, "/api/cert/cert/upload", {"cert":certPEM,"key":keyPEM})` 上传证书。
  2. `parseAcePanelCertID(resp)` 从响应抽取证书 id（兼容 `data.id` / `data.cert_id` / 裸数字，id 可为数字或字符串）。
  3. `client.doJSONRequest(ctx, "/api/cert/cert/{id}/deploy", {"id":certID,"website_id":siteID,"enable_https":true})` 部署并开启 HTTPS。
- 保留 `normalizePrivateKeyPEM` / `verifyKeyCertMatch` 本地预校验；站点 ID 仍取 `svc["site_id"]`（兜底从 `site_name` 的 `名称||ID` 解析）。
- 删除不再使用的 `redactSSL` 辅助函数（原来用于脱敏打印全量站点，现已无 GET 全量站点）。
- 复用既有 `doJSONRequest`（POST + JSON，含 HMAC 签名）。

### 验证
- `go build -tags production ./...` 通过；`read_lints` 对 acepanel.go 无错误。
- 待用户实机用 AcePanel 目标触发部署验证；重点确认：① 上传接口返回 id 的字段名是否与 `parseAcePanelCertID` 兼容（若返回格式特殊，日志会打印原始响应以便修正解析）。② 部署后站点 HTTPS 生效。

### 备注
- 此改动同时规避了之前的 PUT 连接复用 bug（现在全程 POST），故 `panel.go` 的 `DisableKeepAlives` 对 AcePanel 已非必须，但保留以继续保护其他仍用 PUT 的面板。

## AcePanel 部署增加「先查证书列表，命中复用」避免重复上传

### 任务目标
用户指出两步流每次部署都会往 AcePanel 证书库上传一张新证书，造成重复堆积。改为：先 `GET /api/cert/cert?page=N&limit=100` 查证书库，若已有同一张证书则直接复用其 id 部署，未命中才上传。

### 执行细节
- `internal/deploy/acepanel.go` 新增 `findExistingAcePanelCert(ctx, client, certPEM)`：
  - 分页遍历证书列表（limit=100，最多 10 页防御异常 total），响应按 `{msg,data:{items,total}}` 解析，items 为 `map[string]any` 以兼容未知字段名。
  - 匹配策略（确定性优先，宁可漏配不可错配）：① 列表项含 PEM（`cert`/`certificate`/`pem` 字段且含 "BEGIN CERTIFICATE"）时按叶子证书 DER SHA256 指纹比对（复用 `huawei.go` 的 `certFingerprint`/`leafCertDER`）；② 否则按序列号（`serial_number`/`serial` 字段）比对，新增 `serialEqual` 兼容十进制与十六进制（含冒号/空格/`0x` 前缀）表示。
  - 查询/解析失败仅记 DEBUG 日志并返回 false，回退到上传流程，不阻断部署。
- `DeployCert` 流程变为：查列表命中→复用 id；未命中→上传拿 id；然后 `POST /api/cert/cert/{id}/deploy`。
- 新增 import：`bytes`、`crypto/x509`、`math/big`。

### 验证
- `go build -tags production ./...` 通过；lint 无错误。
- 待实机验证：需确认 AcePanel 证书列表项的实际字段名（PEM 内容或序列号字段）是否落在兼容范围内；若列表项两类字段都没有，会始终走上传（行为等同改造前），届时需要用户提供列表接口真实响应以对齐字段。
