# 国际化（i18n）

两套运行时、两套文件，但流程对称：**按前缀拆文件维护 → 脚本合并成主文件 → 代码只读主文件**。

- 后端：Go + go-i18n，主文件 `internal/i18n/locales/{zh-CN,en-US}.json`，编译进二进制。
- 前端：自研轻量 store，主文件 `frontend/src/locales/{zh-CN,en-US}.json`，由 Pinia 加载。

## 1. 目录与生成关系

```
internal/i18n/locales/
├── zh-CN.json            # 生成物，勿手改（Go 只读它）
├── en-US.json
└── split/
    ├── zh-CN/{errors,logs,messages,notifications,other}.json
    └── en-US/{...}

frontend/src/locales/
├── zh-CN.json            # 生成物，勿手改
├── en-US.json
├── locale.ts             # 手写：语言常量（zh-CN / en-US / auto）
└── split/
    ├── zh-CN/{errors,logs,messages,notifications,other}.json
    └── en-US/{...}
```

合并命令：

| 命令                               | 脚本                             | 输出                           |
|------------------------------------|----------------------------------|--------------------------------|
| `make i18n-go` / `make i18n`       | `scripts/merge-go-i18n.sh`       | `internal/i18n/locales/*.json` |
| `make i18n-frontend` / `make i18n` | `scripts/merge-frontend-i18n.sh` | `frontend/src/locales/*.json`  |

脚本用 `jq -s 'reduce .[] as $f ({}; . * $f)'` 深度合并，再整体 `sort_by(.key)`、`from_entries`，并写入一条 `_comment`。**主文件每次都从 split 全量重建**，手改会被覆盖。

> `frontend/src/stores/i18n.ts` 是**手写**的 Pinia store（读 JSON、提供 `t()`），不是生成物。它文件头那句「由 scripts/merge-frontend-i18n.js 自动生成」是历史遗留的错误注释——合并脚本只写 `locales/*.json`，不会碰 store。

## 2. key 归属

按前缀决定放哪个 split 文件，两边规则一致：

| 前缀                                                                    | 文件                 |
|-------------------------------------------------------------------------|----------------------|
| `log.*`                                                                 | `logs.json`          |
| `error.*`、`deploy.error.*`                                             | `errors.json`        |
| `notification.*`                                                        | `notifications.json` |
| `deploy.message.*`、`message.*`                                         | `messages.json`      |
| `app.*`、`menu.*`、`systray.*`、`settings.*`、`updater.*`、其余 UI 文本 | `other.json`         |

命名用点分命名空间 + 语义：`settings.data.export`、`deploy.error.current_cert_parse`、`notification.monitor_expired.title`。同一个 key 可能在 Go 和前端各有一份——**清理前必须 grep 确认归属**，别按前缀猜。

典型容易搞错的例子：数据导入导出对话框标题 `settings.data.export` / `settings.data.import` 由 **Go 后端** `i18n.T()` 调用（`internal/data/backup.go`），不是前端 `t()`。

## 3. 新增 / 修改 key

1. 编辑对应 split 文件（中英各一处，key 必须一致）。
2. 跑 `make i18n`（或单独跑对应脚本）。
3. 提交时**split 文件与主文件一起提交**——主文件是运行时真正读取的那份。
4. 只有主文件变了、split 没变，说明你手改了生成物，回滚重来。

检查是否漏翻：

```bash
# 两边 key 是否一一对应
jq -r 'keys[]' internal/i18n/locales/split/zh-CN/errors.json | sort > /tmp/zh.keys
jq -r 'keys[]' internal/i18n/locales/split/en-US/errors.json | sort > /tmp/en.keys
diff /tmp/zh.keys /tmp/en.keys
```

## 4. Go 侧

`internal/i18n/i18n.go`：

- `//go:embed locales/*.json`，启动时 `bundle.ParseMessageFileBytes` 全部加载；
- 默认语言 `zh-CN`；
- `SetLocale("en-US")` 切英文，其它值一律回落 `zh-CN`——所以 `auto` 不能直接传给后端，必须先解析；
- `T(key, "Name", value, ...)` 用命名参数，模板里写 `{{.Name}}`。

运行期切语言：`main.go` 里 `settingsService.OnChange` 会调 `i18n.SetLocale(s.Language)`。前端把「已解析」的语言（`zh-CN` / `en-US`）写进 `settings.language`，`auto` 只留在 localStorage 里（`Settings.vue` 的 `languageModel` + watch）。

### 4.1 错误信封

`internal/i18n/error.go` 定义了 `i18n.Error{Key, Params, Err}`：

- `Error()` 返回 `译文 + U+001F + key + U+001F + 参数JSON`；
- 前端 `frontend/src/utils/message.ts` 的 `translateBackend()` 解析信封，用前端语言重新翻译；缺 key 或底层错误更长时回退后端译文（避免吞掉云厂商错误码）；
- **落库 / 日志必须用 `TranslateError(err)`**，取不含信封的纯文本，否则会把分隔符写进 `deploy_logs` 或通知正文。

构造错误优先用 `i18n.NewError(key, ...)` / `i18n.Wrap(err, key, ...)`，不要 `fmt.Errorf("中文")`。

## 5. 前端侧

`frontend/src/stores/i18n.ts`：

- `locale`：`zh-CN` / `en-US` / `auto`，持久化在 localStorage 的 `certflow-locale`；
- `resolved`：`auto` 时按 `navigator.language` 解析（`zh*` → 中文，其它 → 英文）；
- `t(key, params)`：先查当前语言，再回落 `zh-CN`，最后返回 key 本身；参数替换 `{name}`。

配套：

- `locales/locale.ts`：语言常量，组件里不要硬编码字符串。
- `utils/naive-locale.ts`：Naive UI 组件的语言包跟随。
- `utils/message.ts`：后端错误信封翻译 + 原生对话框文案截断（500 字符）。
- 主题与语言的完整设计见 [../前端主题与国际化方案.md](../前端主题与国际化方案.md)。

规则：所有用户可见文案走 `t()`；模板里不要拼中文；`console` 里的调试文本不算用户可见，但发布构建会 drop `console`，要留痕就用 `ReportFrontendError`。

## 6. 验证清单

- [ ] split 中英 key 一一对应，没有只在一侧的新 key。
- [ ] `make i18n` 后主文件包含新 key（`jq 'has("your.key")'`）。
- [ ] Go 侧用 `i18n.T()`，前端用 `t()`，没有硬编码文案。
- [ ] 错误路径用 `NewError` / `Wrap`，落库用 `TranslateError`。
- [ ] 断言 i18n 文案的测试检查不含 `error.` / `settings.` / `{{` / `%!`。
- [ ] 清理 key 前 grep 过 Go 与前端两侧。
