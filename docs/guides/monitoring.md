# 监控、扫描与续期提醒

三个能力容易混：

| 能力            | 对象                   | 数据表                                     | 入口                                          |
|-----------------|------------------------|--------------------------------------------|-----------------------------------------------|
| 域名监控        | 你加入列表并启用的域名 | `monitored_domains` + `monitor_check_logs` | `/monitor`                                    |
| 证书扫描        | 任意域名，一次性       | `scan_results`                             | `/scan`                                       |
| 续期 / 过期提醒 | 本应用管理的证书       | `renewal_logs` / `notifications`           | 调度器，见 [certificates.md](certificates.md) |

## 1. 域名监控

页面：`监控`（`/monitor`）。每条记录包含：

| 字段             | 说明                                                |
|------------------|-----------------------------------------------------|
| `domain`         | 域名（唯一）                                        |
| `check_type`     | `https`（默认）/ `http`                             |
| `port`           | 端口，默认 443；HTTP 检查时 80/443 都按默认端口省略 |
| `url`            | 可选，自定义健康检查 URL；空则按域名 + 端口拼       |
| `check_interval` | 检查间隔（秒），默认 3600                           |
| `enabled`        | 是否参与后台检查                                    |

后台循环（`internal/monitor/service.go`）：

- 每 **60 秒** 扫一次「到期该检查」的域名（`last_check_at + check_interval <= now`），单轮最多 **5 个并发**，每个请求带 0–2 秒随机抖动。
- HTTP 客户端按设置缓存（代理 + 自定义 DNS），`http.Client.Timeout` 为 60 秒（Transport 的握手 / 响应头超时各 30 秒）。
- 结果写一条 `monitor_check_logs`，同时更新域名上的快照（证书信息、响应时间、HTTP 状态、错误）。
- 每轮结束 emit `monitor_updated`，前端实时刷新（`Monitor.vue`）。
- 历史按 `monitor_history_days`（默认 90）每天清理一次，启动时也清一次。

### 1.1 状态判定

| 条件                            | 状态      |
|---------------------------------|-----------|
| HTTP 2xx / 3xx                  | `ok`      |
| HTTP 4xx                        | `warning` |
| HTTP 5xx、连接失败、超时        | `error`   |
| 证书剩余天数 ≤ 30 且当前为 `ok` | `warning` |
| 证书剩余天数 ≤ 0                | `expired` |
| 尚未检查                        | `unknown` |

证书信息只从 TLS 握手结果里取：颁发者 / 主体（无 CN 时回退 SAN / O）、有效期、SHA-256 指纹、签名算法、公钥算法与位数、SAN 列表。

### 1.2 通知规则

告警按**状态变化**触发，不是每轮都发（`notifyIfProblem`）：

- `error`：发送错误通知，带错误信息与 HTTP 码；
- `expired`：发送证书过期通知，带颁发者；
- 证书 ≤30 天：发送临期通知；
- HTTP 4xx：发送 HTTP 错误通知；
- 从 `error`/`warning`/`expired` 恢复到 `ok`：发送恢复通知；
- 首次检查就是 `ok`：不打扰。

去重基线在启动时从数据库加载（`loadNotifyBaseline`），所以重启应用不会把已通知过的异常再发一遍。状态没变时只更新快照与历史，不发通知。

### 1.3 手动操作

- 单条「立即检查」：`CheckNow(id)`，同步返回最新快照。
- 设置页「立即检查全部监控」：调 `CheckNow` 的批量入口（前端逐个调用并汇总）。

## 2. 证书扫描

页面：`扫描`（`/scan`）。用于「这个域名现在挂的是什么证书」——不依赖是否已加入监控、也不要求是本应用签发的证书。

- 输入域名、端口（默认 443）、类型（`https`/`http`）。
- 结果包含：颁发者、主题、有效期、剩余天数、指纹、签名算法、公钥算法与位数、SAN、序列号、TLS 握手耗时；失败时写 `error_message`。
- 每次扫描新增一条 `scan_results`；支持单条删除与清空历史。
- 扫描只读取证书，不修改任何配置，也不写 `certificates`。

扫描与监控的区别：扫描是一次性、手动、可针对任意域名；监控是持续、自动、按间隔轮询并产生趋势数据与告警。

## 3. 续期与过期提醒

这两件事由调度器负责，不在监控模块里：

| 任务                          | 间隔                            | 行为                                                        |
|-------------------------------|---------------------------------|-------------------------------------------------------------|
| `auto_renew_certificates`     | `renew_interval` 小时（默认 1） | 续期 `auto_renew && not_after <= now + renewal_days` 的证书 |
| `check_expiring_certificates` | `check_interval` 小时（默认 6） | 对 7 天内到期的证书发提醒；30 天内只做统计日志              |

开关与间隔都在「设置 → 续期」：

- `auto_renew_enabled`：自动续期总闸，关掉后定时任务整轮跳过（手动「立即续期」不受影响）。
- `auto_check_expiry`：关掉后**不注册**过期检查任务，需要重启才生效（代码只在 `Start` 时判断一次）。

实现注意：过期检查对 7 天内到期的证书**每轮都发一次通知**，没有状态去重，所以同一张证书可能每 6 小时提醒一次。觉得吵就把 `check_interval` 调大，或先续期 / 关闭该证书的自动续期并手动处理。

续期任务成功后**不会自动重新部署**，见 [deployment.md](deployment.md) 第 8 节。

## 4. 设置项对照

| 设置                 | 键                        | 默认   | 影响                            |
|----------------------|---------------------------|--------|---------------------------------|
| 自动续期             | `auto_renew_enabled`      | `true` | 定时续期总闸                    |
| 续期间隔（小时）     | `renew_interval`          | `1`    | 续期任务频率                    |
| 自动检查过期         | `auto_check_expiry`       | `true` | 是否注册过期检查任务            |
| 过期检查间隔（小时） | `check_interval`          | `6`    | 过期检查频率                    |
| 监控历史保留（天）   | `monitor_history_days`    | `90`   | `monitor_check_logs` 清理       |
| HTTP 日志保留（天）  | `http_log_retention_days` | `30`   | `httplog.db` 清理，`<=0` 不清理 |

## 5. 排查

| 现象                   | 先看                                                                                 |
|------------------------|--------------------------------------------------------------------------------------|
| 监控一直 `unknown`     | 域名是否 `enabled`、`check_interval` 是否 > 0、应用是否刚启动（首轮在 60 秒内）      |
| 明明能访问却报 `error` | 代理 / 自定义 DNS 是否把请求带偏；证书链是否完整；是否被 WAF 拦了非浏览器 UA         |
| 剩余天数不对           | 看 `cert_not_after` 与 `cert_issuer`，确认连到的是不是预期节点（CDN 可能回不同证书） |
| 通知太多               | 状态未变不会发；重复的是「7 天内到期」那类，调大 `check_interval` 或先处理证书       |
| 扫描成功但监控失败     | 两者用的 URL/端口不同：监控默认按 `domain:port` 拼，扫描用你填的端口                 |
| 历史趋势断档           | 应用没运行时不会检查；历史按保留天数清理，超出就没了                                 |

日志位置与通用处置见 [../troubleshooting.md](../troubleshooting.md) 第 6 节。
