# 前端统一主题与国际化（i18n）方案

> 本文档提炼自 certflow 前端，目标是沉淀一套**可复用到其他项目的统一规范**：
> 主题（深/浅/跟随系统）、配色与 CSS 变量、naive-ui 主题覆盖、以及语言（中/英/跟随系统）切换机制。
> 技术栈：Vue 3 + TypeScript + Pinia + TailwindCSS v4 + naive-ui。
> i18n 为**自研轻量方案**（基于 `*.json` + Pinia store 的 `t()`，**不是** vue-i18n 包，零额外依赖）。

---

## 一、整体架构

主题与语言都通过 **Pinia store** 作为唯一真相源（single source of truth），并持久化到 `localStorage`。

```
App.vue (根)
├── NConfigProvider  ← 注入 theme / locale / dateLocale / theme-overrides
│   ├── useThemeStore   → isDark / setTheme
│   ├── useI18nStore    → t() / setLocale / resolved
│   └── useNaiveLocale  → naiveLocale / naiveDateLocale（naive 内置组件文案跟随）
└── 全局 CSS 变量（--app-text-color 等）由 isDark 计算后注入 :root
```

**关键约定**：
- 模板里颜色一律用 Tailwind 的 `dark:` 变体或 CSS 变量，**禁止写死颜色值**（除少量日志高亮等特例）。
- 主题/语言选择保留 `auto` 选项；`auto` 在 store 内解析为具体值，**持久化与展示都用原始选择（含 auto），后端/判断才用解析值**。
- 切换语言后，naive-ui 内置组件（日期选择器、分页、空状态）文案**自动跟随**，无需逐个处理。

## 二、主题系统

### 2.1 三种模式

```ts
// stores/theme.ts
export type ThemeMode = 'dark' | 'light' | 'auto'
const STORAGE_KEY = 'certflow-theme' // 持久化 key，复用项目请改前缀
```

| 模式 | 行为 |
|------|------|
| `light` | 强制浅色 |
| `dark`  | 强制深色 |
| `auto`  | 跟随系统（通过后端/系统 API 探测 `IsDarkMode()`，监听变化）|

### 2.2 核心 store（可直接复用）

```ts
// stores/theme.ts —— 精简骨架，去掉了 certflow 专属的窗口外观同步
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'
import { darkTheme, lightTheme } from 'naive-ui'
import type { GlobalThemeOverrides } from 'naive-ui'

export type ThemeMode = 'dark' | 'light' | 'auto'
const STORAGE_KEY = 'certflow-theme'

// naive-ui 主题覆盖：统一圆角、字体等品牌视觉
const baseThemeOverrides: GlobalThemeOverrides = {
  common: {
    borderRadius: '8px',
    fontFamily: "'PingFang SC', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif",
  },
  Card: { borderRadius: '12px' },
  Button: { borderRadiusMedium: '8px' },
  Input: { borderRadius: '8px' },
  Tag: { borderRadius: '9999px' },
}

export const useThemeStore = defineStore('theme', () => {
  const theme = ref<ThemeMode>((localStorage.getItem(STORAGE_KEY) as ThemeMode) || 'auto')
  const systemDark = ref(false) // 由系统 API 填充，纯 Web 项目可用 matchMedia 监听

  const isDark = computed(() => (theme.value === 'auto' ? systemDark.value : theme.value === 'dark'))
  const naiveTheme = computed(() => (isDark.value ? darkTheme : lightTheme))
  // 注意：真实源码此处带 isDark 分支（虽恒等），保留分支便于将来按主题定制覆盖
  const naiveThemeOverrides = computed(() =>
    isDark.value ? baseThemeOverrides : baseThemeOverrides,
  )

  function setTheme(mode: ThemeMode) {
    theme.value = mode
    localStorage.setItem(STORAGE_KEY, mode)
  }

  // 初始化系统主题探测（纯 Web 示例用 matchMedia）
  function initTheme() {
    if (typeof window !== 'undefined' && window.matchMedia) {
      const mq = window.matchMedia('(prefers-color-scheme: dark)')
      systemDark.value = mq.matches
      mq.addEventListener('change', (e) => (systemDark.value = e.matches))
    }
  }
  initTheme()

  // 跨标签页同步
  window.addEventListener('storage', (e) => {
    if (e.key === STORAGE_KEY && e.newValue) theme.value = e.newValue as ThemeMode
  })

  return { theme, isDark, naiveTheme, naiveThemeOverrides, setTheme }
})
```

> **纯 Web 项目注意**：certflow 用 `SystemService.IsDarkMode()`（Wails 后端）探测系统主题；
> 纯前端用 `window.matchMedia('(prefers-color-scheme: dark)')` 替代，其余逻辑一致。

## 三、配色方案

### 3.1 设计色板（深浅双主题）

| 用途 | 浅色 (light) | 深色 (dark) |
|------|-------------|------------|
| 主背景 | `#ffffff` | `#1a1a2e` |
| 文本主色 | `#1a1a2e` | `#e5e5e5` |
| 文本次要 | `rgba(0,0,0,0.6)` | `rgba(255,255,255,0.6)` |
| 文本弱化 | `rgba(0,0,0,0.4)` | `rgba(255,255,255,0.4)` |
| 面板/卡片（毛玻璃）| `bg-white/80` | `dark:bg-neutral-900/80` |
| 边框 | `border-neutral-200` | `dark:border-neutral-700` |
| 主强调色（蓝）| `blue-500`（hex `#3b82f6`）| `blue-500`（`dark:text-blue-400`，hex `#60a5fa`）|
| 渐变（文字/品牌）| `from-blue-500 to-purple-500` | 同左 |

### 3.1.1 语义状态色（固定值，不随主题切换）

项目统一使用 Tailwind 预设色，跨组件一致：

| 语义 | 颜色类 | hex |
|------|--------|-----|
| 主品牌蓝 | `text-blue-500` | `#3b82f6` |
| 成功/正常 | `text-green-500` | `#22c55e` |
| 警告 | `text-yellow-500` | `#eab308` |
| 错误/危险 | `text-red-500` | `#ef4444` |
| 错误（深色细化）| `text-red-400` | `#f87171` |
| 链接/可点击 | `text-blue-500 hover:text-blue-600` | `#3b82f6` / `#2563eb` |

> **用法范式**（`utils/certificate.ts` 证书过期判断）：
> ```ts
> if (days <= 7) return 'text-red-500 bg-red-50 dark:bg-red-900/30'   // 紧急
> else if (days <= 30) return 'text-yellow-500 bg-yellow-50 dark:bg-yellow-900/30'  // 即将过期
> else return 'text-green-500 bg-green-50 dark:bg-green-900/30'       // 正常
> ```
> 状态色在深浅主题下均带 `dark:bg-xxx-900/30` 浅底，保证对比度。

### 3.2 Tailwind 双主题写法（核心规范）

项目使用 **TailwindCSS v4**，深浅切换**不依赖 `.dark` class**（naive-ui 的 `darkTheme` 不自动给 `<html>` 加 class），而是：

```vue
<!-- ✅ 正确：用 isDark computed + Tailwind dark: 变体，或直接绑定 style -->
<div class="bg-white dark:bg-neutral-900 border-neutral-200 dark:border-neutral-700">
```

```ts
// 在组件内：从 theme store 取 isDark，配合 Tailwind dark: 前缀
import { storeToRefs } from 'pinia'
import { useThemeStore } from './stores/theme'
const { isDark } = storeToRefs(useThemeStore())
```

> **深浅切换机制说明（重要）**：
> - naive-ui 主题由 `isDark` computed 驱动（`NConfigProvider :theme`），与 Tailwind 的 `dark:` 是**两套独立系统**。
> - 项目中 Tailwind `dark:` 变体**实际生效方式**取决于 Tailwind v4 的 `dark` 策略配置（默认 `prefers-color-scheme`）。
>   certflow 在组件内普遍用 `isDark` 直接控制关键色（如 `:class="isDark ? 'text-blue-400' : 'text-blue-500'"`），
>   `dark:` 作为补充写法。
> - **复用建议**：若你希望 `dark:` 严格跟随 `isDark`（而非系统偏好），需在 `tailwind.config` 设 `dark: 'class'`，
>   并在 `isDark` 变化时 `document.documentElement.classList.toggle('dark', isDark)`。否则 `dark:` 仍按系统偏好生效，
>   可能与 naive-ui 强制主题不一致——此时以 `isDark` 直接控制为准。

## 四、国际化（i18n）

### 4.1 语言三态

```ts
// stores/i18n.ts
export type Locale = 'zh-CN' | 'en-US' | 'auto'
type ResolvedLocale = 'zh-CN' | 'en-US'
const STORAGE_KEY = 'certflow-locale' // 复用项目改前缀
```

- `auto`：跟随浏览器 `navigator.language`（`zh` 开头 → 中文，否则英文）。
- `resolved`：计算属性，把 `auto` 解析为具体语言，供翻译和逻辑判断使用。
- 持久化存**原始选择**（含 auto），展示用原始值，判断用 `resolved`。

### 4.2 轻量 i18n store（替代 vue-i18n，零依赖）

```ts
// stores/i18n.ts 核心
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'
import zhCN from '../locales/zh-CN.json'
import enUS from '../locales/en-US.json'

function getSystemLocale(): ResolvedLocale {
  const lang = navigator.language || ''
  return lang.startsWith('zh') ? 'zh-CN' : 'en-US'
}

const messages = { 'zh-CN': zhCN, 'en-US': enUS }

export const useI18nStore = defineStore('i18n', () => {
  const locale = ref<Locale>((localStorage.getItem('certflow-locale') as Locale) || 'auto')
  const LOCALE_KEY = 'certflow-locale'

  // 解析后的语言（不含 auto）：auto 跟随系统语言
  const resolved = computed<ResolvedLocale>(() => {
    if (locale.value === 'auto') return getSystemLocale()
    return locale.value
  })

  const getLocale = (): Locale => locale.value
  const getResolvedLocale = (): ResolvedLocale => resolved.value

  const setLocale = (newLocale: Locale) => {
    locale.value = newLocale
    localStorage.setItem(LOCALE_KEY, newLocale)
  }

  const t = (key: string, params?: Record<string, string | number>): string => {
    const msg = messages[resolved.value]?.[key] || messages['zh-CN']?.[key] || key
    if (!params) return msg
    return Object.entries(params).reduce(
      (str, [k, v]) => str.replace(new RegExp(`\\{${k}\\}`, 'g'), String(v)), str,
    )
  }

  return { locale, resolved, getLocale, getResolvedLocale, t, setLocale }
})

// 对外导出解析后语言类型（供其他模块 import 类型用）
export type { ResolvedLocale }
```

**用法**：
```vue
<script setup>
import { useI18nStore } from './stores/i18n'
const { t } = useI18nStore()
</script>
<template>
  <span>{{ t('settings.title') }}</span>
  <!-- 带参：t('log.load', { data: 'xxx' }) -->
</template>
```

### 4.4 naive-ui 组件语言跟随

naive-ui 内置组件（日期选择器、分页等）有独立的 locale 体系，需单独桥接：

```ts
// utils/naive-locale.ts
import { computed } from 'vue'
import { zhCN, dateZhCN, enUS, dateEnUS } from 'naive-ui'
import { useI18nStore } from '../stores/i18n'

export function useNaiveLocale() {
  const i18n = useI18nStore()
  const naiveLocale = computed(() => (i18n.resolved === 'zh-CN' ? zhCN : enUS))
  const naiveDateLocale = computed(() => (i18n.resolved === 'zh-CN' ? dateZhCN : dateEnUS))
  return { naiveLocale, naiveDateLocale }
}
```

在 `App.vue` 注入：
```vue
<n-config-provider :locale="naiveLocale" :date-locale="naiveDateLocale" ...>
```

### 4.5 翻译文件组织（拆分 + 合并）

为便于多人维护，翻译 JSON 按类型拆分，再合并为单一文件：

```
src/locales/
├── split/
│   ├── zh-CN/  (errors.json / logs.json / messages.json / notifications.json / other.json)
│   └── en-US/  (同上)
├── zh-CN.json   ← 合并产物（自动生成）
├── en-US.json   ← 合并产物（自动生成）
└── locale.ts    ← 语言常量
```

**维护流程**：
1. 编辑 `split/<lang>/<type>.json` 新增/修改 key。
2. 运行合并脚本（见下方）生成 `zh-CN.json` / `en-US.json`。
3. **`*.json` 合并产物不要手改**，只在 split 里改。

合并脚本示例（`scripts/merge-frontend-i18n.js` 思路）：
```js
// 伪代码：读取 split/zh-CN/* 合并为 zh-CN.json，en-US 同理
const fs = require('fs')
const path = require('path')
function merge(dir) {
  const out = {}
  for (const f of fs.readdirSync(dir)) {
    if (f.endsWith('.json')) Object.assign(out, JSON.parse(fs.readFileSync(path.join(dir, f))))
  }
  return out
}
fs.writeFileSync('src/locales/zh-CN.json', JSON.stringify(merge('src/locales/split/zh-CN'), null, 2))
```

## 五、设置页切换 UI（范式）

```ts
// Settings.vue 范式
const themeStore = useThemeStore()
const { setTheme } = themeStore
const themeModel = computed({
  get: () => themeStore.theme,

const i18nStore = useI18nStore()
const languageModel = computed({
  get: () => i18nStore.locale,

const themeOptions = [
  { label: t('theme.auto'), value: 'auto' },
  { label: t('theme.dark'), value: 'dark' },
  { label: t('theme.light'), value: 'light' },
]
```
